llama.cpp

Only needed if you run llama-server and want to see or manage its models from Vocalis. Leave this blank otherwise — nothing else in Vocalis uses it, and the LLM ▸ llama.cpp tab is the only thing affected.
The URL is all that is required. An API key is only needed if llama-server was started with --api-key; leave it blank if it was not, and the tab still works. (VOCALIS_LLAMA_URL / VOCALIS_LLAMA_API_KEY override these.)
llama-server must listen on more than loopback (start it with --host 0.0.0.0, or the machine's LAN address), and 127.0.0.1 here would be this container itself, so use host.docker.internal for a llama-server on this machine.

Same warning as the KoboldCpp section above, for this engine, and the same switch: Warn me if I enable a device… under Devices above turns it off for both engines and for the reverse direction. Only applies when llama-server is on this machine — a model loading on another box is not sharing these cards.
Loading and unloading models from here needs llama-server started in router mode — that is, with no -m, pointed at a --models-dir or a --models-preset file. Started with a fixed model it still works here, read-only: you see which model, its context and its cache behavior, but there is nothing to load. On a two-card box also pass --models-max 1, or the router will hold several models at once and load one whenever anything asks for it.
